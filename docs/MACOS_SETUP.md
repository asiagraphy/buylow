# macOS 설치와 증권사 설정

uv 기반 설치와 LEAN 백테스트는 macOS에서 검증했습니다. 증권사 계좌를 이용한
주문·취소·체결 검증은 아직 수행하지 않았습니다. 현재 토스 어댑터는 실거래용이며,
토스 시세를 사용하는 로컬 모의체결 기능은 아직 없습니다.

## 실행환경

| 항목 | 용도 | 설정 방법 |
|---|---|---|
| uv | Python 설치와 의존성 동기화 | uv를 설치하고 아래 명령을 실행합니다. |
| Python 3.11 | LEAN이 내장하는 Python 런타임 | `uv python install 3.11` |
| .NET 10 SDK | LEAN 런처와 증권사 어댑터 빌드 | .NET 10 SDK를 설치합니다. |
| Git | 저장소 관리 | 저장소를 복제한 폴더에서 명령을 실행합니다. |

```bash
uv python install 3.11
uv sync --locked
uv run --locked python -m orchestrator.lean --prepare
scripts/build-adapter.sh
```

`--prepare`와 어댑터 빌드는 서버나 자동매매를 시작하지 않습니다. Python 버전은
`.python-version`, 의존성 선언은 `pyproject.toml`, 정확한 설치 버전은 `uv.lock`이
관리합니다. uv가 관리하는 환경을 수동으로 활성화할 필요는 없습니다.

개발 의존성을 제외하려면 `uv sync --locked --no-dev`를 사용합니다. 테스트는
`uv run --locked pytest`로 실행합니다. `uvx`는 별도 도구를 격리 실행하는 명령이므로
이 프로젝트의 서버와 테스트는 `uv run`으로 실행합니다.

## 토스 인증과 허용 IP

토스증권 WTS의 **설정 > Open API**에서 다음을 설정합니다.

1. 클라이언트를 등록하고 Client ID와 Client Secret을 발급받습니다.
2. **허용 IP 관리**에 이 프로그램이 API에 접속할 때 사용하는 공인 IP를 등록합니다.
   사설 LAN 주소나 `127.0.0.1`은 API 서버가 보는 출발지 IP가 아닙니다.
   VPN이나 네트워크를 변경하면 허용 IP도 다시 확인해야 합니다.
3. 국내 주문에 필요한 투자자지시 거래소 설정은 통합(SOR)이어야 합니다.
   특정 종목의 사전 동의·교육 등이 필요하면 토스 앱에서 완료합니다.

이 설정은 API 호출 주체를 인증하고 허용된 접속지에서만 계좌를 사용하도록 하기 위한
것입니다. 계좌번호를 별도로 입력하지 않아도 프로그램이 계좌 목록의 `accountSeq`를
조회해 요청 헤더에 사용합니다.

근거: [공식 시작 안내](https://developers.tossinvest.com/docs),
[인증·접속 FAQ](https://developers.tossinvest.com/docs/faq).

## 키를 로컬에 저장하는 방법

대시보드의 설정 탭 또는 `.env`를 사용합니다. 같은 키가 양쪽에 있으면 환경변수가
우선합니다. `.env`는 자동으로 읽지 않으므로 실행할 때 `--env-file .env`를 지정합니다.

```dotenv
BUYLOW_BROKER=toss
BUYLOW_TOSS_CLIENT_ID=
BUYLOW_TOSS_CLIENT_SECRET=
```

빈 값에 발급받은 키를 입력하세요. 실제 키를 저장소나 메시지에 넣지 마세요.
`.env`와 `config.local.yaml`은 Git 추적에서 제외됩니다. 파일 권한은 소유자만
읽도록 제한할 수 있습니다.

```bash
chmod 600 .env
```

계좌를 사용하지 않는 현재가 조회부터 확인할 수 있습니다. 최초 호출에는 OAuth 토큰이
발급되고, 이후 Python과 C# 클라이언트가 토큰 캐시를 공유합니다. 토스는 클라이언트당
유효한 토큰이 하나이므로 다른 프로그램에서 토큰을 발급하면 기존 토큰이 무효화될 수 있습니다.

```bash
uv run --locked --env-file .env python -m brokers.toss prices --symbols 005930
uv run --locked --env-file .env python -m brokers.toss buying-power --currency KRW
```

위 명령은 조회 전용입니다. HTTP 401이면 키와 토큰 상태를, HTTP 403이면 허용 IP를
확인하세요. HTTP 429이면 호출 한도와 응답의 `Retry-After`를 확인합니다.

## 대시보드와 데이터

```bash
uv run --locked --env-file .env python -m orchestrator.api
```

브라우저에서 `http://127.0.0.1:8420`을 엽니다. 자동매매가 켜진 설정을 유지한 채
서버를 다시 시작하면 거래도 재개됩니다. 처음 설정할 때는 자동매매를 꺼 둡니다.
환경변수 `BUYLOW_LIVE_ENABLED`는 저장된 토글보다 우선하므로 일반적인 대시보드
운영에서는 지정하지 않는 편이 명확합니다.

데이터 탭에서 가격 데이터를 준비하고, 전략을 저장한 뒤 백테스트를 실행합니다.
현재 일봉·수급·펀더멘털 수집은 pykrx 경로를 사용합니다. KRX ID와 비밀번호는
그 경로의 인증이 필요한 데이터에 사용하며, 토스 API 키와 별개입니다.
KRX 데이터 경로의 토스 대체는 데이터 항목과 범위를 대조한 뒤 결정해야 합니다.

토스 분봉은 봉 종료 시각을 돌려주므로 프로그램은 LEAN 저장 형식에 맞게 1분을
뺍니다. 이전 버전에서 저장한 분봉 파일은 자동으로 변경하지 않습니다. 공식 FAQ에
따르면 토스 국내 시세는 KRX+NXT 통합 데이터이며, 거래소별 분리는 제공되지 않습니다.
[시세·캔들 FAQ](https://developers.tossinvest.com/docs/faq)

## 모의투자와 실거래의 차이

현재 구현된 증권사 모의투자는 KIS의 `kis_demo`입니다. 필요한 항목은 모의 App Key,
App Secret, 계좌번호, HTS ID이며, 실전 키와 구분해서 설정 탭에 저장합니다.

토스의 공개 명세에는 production 서버만 기재되어 있고, 현재 저장소의 토스 어댑터는
실제 주문을 전송합니다. 토스 기반 모의투자는 별도의 로컬 가상체결 구현이 필요합니다.
백테스트가 통과했다는 사실은 실시간 모의투자나 실제 계좌 주문이 검증됐다는 뜻이 아닙니다.

실거래 전에는 저장 전략, 대상종목, 주문금액 한도, 기존 보유와 미체결 주문을 확인해야
합니다. 현재 전략은 계좌 전체 자산을 기준으로 목표 비중을 계산합니다. 주문금액 한도는
전략의 총 투자예산을 제한하는 설정이 아닙니다.

주문 응답 유실 등으로 접수 여부를 알 수 없으면 자동매매가 꺼지고 프로세스가
종료됩니다. 증권사 앱의 미체결·체결내역을 대조한 뒤 수동으로 재개해야 합니다.
일반적인 자동매매 중지는 이미 증권사에 접수된 주문을 취소하거나 보유 주식을
청산하지 않습니다.

KIS의 미체결 주문 복구, 토스의 인증 갱신·정정·취소·체결 확인은 실제 계좌에서
추가 검증이 필요합니다. 관련 구현과 검증 범위는 [검토 기록](./UV_MIGRATION.md)에 있습니다.
